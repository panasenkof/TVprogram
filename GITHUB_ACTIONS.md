# Еженедельная телепрограмма в GitHub Actions

Сервер GitHub сам запускает скрипты каждое воскресенье в **10:00 по Москве**.
Компьютер и Cursor можно выключить. Ключи LLM и платная подписка Cursor для
этого сценария не нужны: всю работу делают скрипты из репозитория.

## 1. Включить workflow в основной ветке

Изменения должны находиться в основной ветке `main`. Если они пришли через PR,
откройте PR, дождитесь успешной проверки **Automation checks** и нажмите
**Merge pull request → Confirm merge**. Пока workflow только в ветке PR,
еженедельное расписание не работает.

Откройте [Actions репозитория](https://github.com/panasenkof/TVprogram/actions).
Слева должен появиться **Weekly TV programme**.

Если Actions отключены, откройте **Settings → Actions → General** и разрешите
GitHub Actions. Используются только официальные actions из `actions/*`.
Для workflow достаточно прав **Read repository contents**. Разрешение создавать
PR, собственный GitHub-токен и отдельный Environment не нужны.

## 2. Подготовить три секрета

| Имя Repository secret | Значение | Обязательность |
| --- | --- | --- |
| `YADISK_TOKEN` | OAuth-токен аккаунта Яндекса, где находится `/Панасенко/Телепрограмма/` | Нужен для загрузки на Диск |
| `TELEGRAM_BOT_TOKEN` | Токен существующего или нового Telegram-бота | Для уведомлений |
| `TELEGRAM_CHAT_ID` | Числовой ID вашего чата с ботом или группы | Для уведомлений |

Секреты Cursor автоматически в GitHub не переносятся. Если у вас сохранены
рабочие значения для старой автоматизации, используйте те же значения.
GitHub после сохранения не показывает содержимое секрета; его можно заменить.
В репозиторий, issues и сообщения с отчётом токены вставлять не нужно.

### Получить `YADISK_TOKEN`

1. Войдите в Яндекс под тем аккаунтом, на Диск которого нужно складывать файлы.
2. Откройте [Яндекс OAuth](https://oauth.yandex.ru/) и создайте приложение.
   Название, например: **TVprogram GitHub Actions**. Если уже есть своё
   OAuth-приложение для Cursor, можно использовать его.
3. На шаге выбора платформ укажите веб-сервис. В **Redirect URI** впишите
   `https://oauth.yandex.ru/verification_code` (в интерфейсе может быть кнопка
   подстановки URL для разработки).
4. В доступах к данным добавьте оба разрешения Яндекс Диска:
   **Чтение всего Диска** (`cloud_api:disk.read`) и
   **Запись в любом месте на Диске** (`cloud_api:disk.write`).
   Права только на папку приложения недостаточны для `/Панасенко/Телепрограмма/`.
   Чтение нужно для проверки уже созданной папки и размера/хеша загруженного файла.
5. Сохраните приложение. Скопируйте его **ClientID**.
6. Откройте в браузере следующий адрес, заменив `ВАШ_CLIENT_ID`:

   ```text
   https://oauth.yandex.ru/authorize?response_type=token&client_id=ВАШ_CLIENT_ID
   ```

7. Разрешите доступ. Скопируйте выданный OAuth-токен. Если он показан в адресе
   после `access_token=`, берите только его значение, до следующего `&`.
8. Это и есть значение `YADISK_TOKEN`. Пароль Яндекса, ClientID и Client secret
   в этот секрет не подходят.

Скрипт создаст папки `/Панасенко` и `/Панасенко/Телепрограмма`, если их ещё нет.
Они создаются в корне Диска того аккаунта, который выдал токен. Файлы остаются
личными: workflow не публикует ссылки общего доступа.

Если токен истёк или отозван, повторите выдачу и замените `YADISK_TOKEN` в GitHub.

### Получить `TELEGRAM_BOT_TOKEN`

Если старый бот уже присылает отчёты Cursor, используйте его токен. Создавать
второго бота не обязательно.

1. В Telegram откройте официального [@BotFather](https://t.me/BotFather).
2. Для существующего бота отправьте `/mybots`, выберите бота, затем **API Token**.
   Если токен утерян, при перевыпуске обновите также старую автоматизацию,
   если продолжаете её использовать.
3. Для нового бота отправьте `/newbot`, задайте имя и username по подсказкам.
4. Скопируйте токен вида `123456789:AA...` в секрет `TELEGRAM_BOT_TOKEN`.
5. Откройте созданного бота, нажмите **Start / Запустить** и отправьте обычное
   сообщение. Бот сможет написать вам только после того, как вы начали с ним чат.

### Узнать `TELEGRAM_CHAT_ID`

Лучший вариант при переносе — тот же числовой ID, который уже использует Cursor.
Если значения нет под рукой:

1. Отправьте боту в личный чат сообщение, например `Проверка телепрограммы`.
2. Откройте PowerShell на компьютере и выполните код ниже. Он спросит токен
   скрытым вводом и выведет только ID и имя чата. Токен не вставляйте в сам код.

   ```powershell
   $tvBotSecret = Read-Host 'Токен Telegram-бота' -AsSecureString
   $tvBotPlain = [System.Net.NetworkCredential]::new('', $tvBotSecret).Password
   try {
       $tvUpdates = Invoke-RestMethod -Method Get -Uri ('https://api.telegram.org/bot{0}/getUpdates' -f $tvBotPlain)
       $tvUpdates.result | ForEach-Object {
           if ($_.message) {
               [pscustomobject]@{
                   ChatID = $_.message.chat.id
                   Name = $_.message.chat.first_name
                   Group = $_.message.chat.title
               }
           }
       } | Format-Table -AutoSize
   } catch {
       Write-Host 'Не удалось получить обновления. Проверьте токен и подключение.'
   } finally {
       $tvBotPlain = $null
       $tvBotSecret = $null
   }
   ```

3. Найдите свой чат по имени. Скопируйте **ChatID** в `TELEGRAM_CHAT_ID`.
   Для личного чата это обычно положительное число. Для группы ID может
   начинаться с `-100`: минус сохраняйте. Username вида `@имя` сюда не нужен.
4. Если таблица пуста, напишите боту новое сообщение и сразу повторите запрос.
   Telegram хранит необработанные обновления ограниченное время. Если другой
   процесс опрашивает `getUpdates`, он мог уже забрать сообщение.
5. Если у бота настроен webhook, `getUpdates` недоступен. Возьмите ID из текущих
   настроек Cursor либо создайте отдельного бота для этой автоматизации.
   Удалять webhook действующего бота для настройки телепрограммы не нужно.

Для отчётов в группу добавьте бота в нужную группу, отправьте там команду
`/start@username_бота`, затем найдите именно эту группу в результате запроса.
Для обычной отправки отчётов в личный чат права администратора не нужны.

## 3. Сохранить значения в GitHub

1. Откройте [настройки секретов TVprogram](https://github.com/panasenkof/TVprogram/settings/secrets/actions).
   Это **Settings → Secrets and variables → Actions**.
2. Выберите вкладку **Secrets**, затем **New repository secret**.
3. В **Name** введите `YADISK_TOKEN`, в **Secret** вставьте OAuth-токен. Нажмите
   **Add secret**.
4. Аналогично создайте `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`.
5. Проверьте, что видны все три имени именно в **Repository secrets** этого
   репозитория. Раздел Variables для токенов не используйте.

Если Telegram-секретов нет, файлы всё равно собираются и загружаются на Диск,
а в отчёте указывается, что уведомление пропущено. Если нет `YADISK_TOKEN`,
обычный запуск отмечается ошибкой загрузки, но готовые документы сохраняются
в GitHub и отчёт всё равно отправляется, если Telegram настроен.

## 4. Сделать пробный запуск без внешних действий

1. Откройте **Actions → Weekly TV programme → Run workflow**.
2. Выберите ветку **main**.
3. Оставьте включённым параметр **Пробная сборка: без Яндекс Диска и Telegram**
   (`dry_run = true`). Этот режим работает даже без секретов.
4. Нажмите **Run workflow** и откройте появившийся запуск. Установка LibreOffice
   и загрузка сетки могут занять несколько минут.
5. В **Summary** проверьте даты недели, число страниц и замечания по источникам.
6. Внизу страницы в **Artifacts** скачайте `tv-programme-...`. В ZIP находятся:
   DOCX/PDF, `report.txt`, `build-report.json`, `layout.json`, `pdf-check.json`,
   журналы этапов и папка `previews` с началом, серединой и концом PDF.
7. Откройте PDF и превью: есть все ожидаемые дни/каналы, блоки целые, пустых
   листов нет. После группировки обычно получается около 22–24 страниц,
   но объём зависит от сетки. Автоматическая проверка сравнивает все строки
   PDF с нужными страницами и колонками, а не требует фиксированное число листов.

Автоматический контроль текста и координат не заменяет визуальное чтение:
превью оставлены для проверки человеком. Никакая LLM в workflow не запускается.

## 5. Проверить настоящий запуск

После сохранения секретов повторите **Run workflow** на `main`, но снимите
галочку пробной сборки (`dry_run = false`).

Перед загрузкой проверяется полнота: нужны правильные даты понедельник–воскресенье,
все семь дней и именно **следующая** неделя. Не допускается более 10 пропущенных
канал-дней из 105 и более трёх отсутствующих каналов за один день.
Если источники доступны лишь для текущей или существенно неполной недели,
документы и диагностический отчёт сохраняются в артефактах GitHub, но **на
Яндекс Диск не загружаются**, чтобы не перезаписать существующие файлы
устаревшими/неполными. В Telegram указывается причина отказа публикации.

Проверьте:

- запуск завершился успешно;
- на Яндекс Диске появилась папка **Панасенко → Телепрограмма** с двумя файлами;
- имена имеют вид `programma-YYYY-MM-DD.docx` и `programma-YYYY-MM-DD.pdf`, где
  дата — понедельник реально собранной недели из `build-report.json`;
- в Telegram пришёл тот же итоговый отчёт, что записан в Summary и `report.txt`.

Повторный запуск для той же недели **перезапишет** эти два файла на Диске,
добавив при необходимости ранее отсутствовавшие передачи. Имена и папка
совпадают с прежней автоматизацией Cursor. Остальные файлы workflow не удаляет.

После успешной проверки отключите старое воскресное расписание в Cursor,
чтобы не было двух сборок и двух сообщений. Из GitHub отключить Cursor-задачу
нельзя. После этого ждать ближайшего воскресенья для обычной работы не нужно.

## 6. Как работает расписание и выбор недели

В `.github/workflows/weekly-tv.yml` записано `0 7 * * 0`: воскресенье,
07:00 UTC = **10:00 Europe/Moscow**. Часовой пояс сборки тоже Москва.
Расписание начинает работать после появления workflow в `main`.

GitHub может задерживать запуск при нагрузке, особенно в начале часа;
старт ровно в 10:00:00 не гарантируется. При необходимости можно вручную
запустить тот же workflow. Одновременные сборки выполняются последовательно.

Сохранён прежний алгоритм: в воскресенье следующая неделя начинается завтра.
В остальные дни выбирается понедельник после ближайшего воскресенья. Если
следующая неделя отсутствует в индексе Телеграфа, скрипт всё равно проверяет
Яндекс ТВ. Только если оба источника не дают пригодной сетки, используется
текущая неделя с явным сообщением в отчёте. Если запуск задержался до понедельника,
используется фактическая дата запуска, как в прежнем сценарии Cursor.
Дату в имени нельзя подменять датой воскресенья или текущим числом.

Если каких-то дней/каналов нет в источниках, скрипт не придумывает сетку,
собирает доступное и указывает пропуски. Замена Яндекса данными Телеграфа
также отражается в отчёте. Статус **частично** при этом возможен даже при
успешном (зелёном) workflow. При полном отсутствии сетки — ошибка.

## 7. Где смотреть ошибки и как восстановить работу

При ошибке сборки/загрузки шаг подготовки отчёта и отправка Telegram запускаются
всё равно. В сообщении будет этап ошибки, даты (если уже известны), число страниц
и список файлов, которые действительно успели загрузиться и пройти проверку.
При полном отказе GitHub/раннера, принудительной остановке либо превышении
общего лимита job финальные шаги могут не выполниться; это ограничение среды.

| Ситуация | Что сделать |
| --- | --- |
| `Не задан секрет YADISK_TOKEN` | Создайте Repository secret с точным именем |
| Яндекс HTTP 401 | Получите свежий OAuth-токен и замените секрет |
| Яндекс HTTP 403 | Проверьте разрешения `disk.read` и `disk.write`, затем перевыдайте токен |
| Яндекс HTTP 507 | Освободите место на Диске |
| Ошибка SHA-256/размера | Повторите запуск; проверьте состояние сервиса Диска |
| Источники недоступны / сетки нет | Посмотрите `build-week.log` и `build-report.json`, повторите позже |
| PDF не прошёл проверку | Изучите `layout.json`/журналы и превью; такой PDF на Диск не отправляется |
| Telegram пропущен | Задайте оба Telegram-секрета; без них сборка не падает |
| Telegram не принял отчёт | Проверьте токен, ChatID, Start у бота и право писать в выбранный чат |
| Нет кнопки Run workflow | Убедитесь, что workflow уже в `main`, Actions разрешены и у вас права записи |

Отчёты и документы в GitHub хранятся 30 дней; копии на Яндекс Диске не имеют
такого ограничения. Приватный репозиторий использует ваш лимит GitHub Actions:
текущий расход можно посмотреть в настройках GitHub **Billing and licensing**.

## Проверки при изменении кода

Workflow **Automation checks** на PR и push проверяет обработку ошибок,
выбор недели, API загрузки без реальных токенов и полную цепочку вёрстки
на примере из репозитория. Он не ходит за сеткой и не отправляет файлы/сообщения.

Локально при установленных зависимостях, LibreOffice и Poppler:

```bash
python3 -m unittest discover -s tests -v
python3 scripts/smoke_render.py
```

Официальные инструкции: [расписание GitHub Actions](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule),
[секреты репозитория](https://docs.github.com/en/actions/how-tos/write-workflows/choose-what-workflows-do/use-secrets),
[доступ к API Диска](https://yandex.ru/dev/disk/api/concepts/quickstart.html),
[выдача OAuth-токена вручную](https://yandex.ru/dev/id/doc/ru/tokens/debug-token),
[Telegram BotFather](https://core.telegram.org/bots/tutorial#obtain-your-bot-token).
